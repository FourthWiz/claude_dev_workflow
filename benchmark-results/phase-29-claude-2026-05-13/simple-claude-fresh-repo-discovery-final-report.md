# Simple Claude Fresh Repo Discovery Report

## Project Purpose

Quoin is a workflow-memory toolkit for stateless coding agents. It provides 21
slash-command skills that structure engineering work — planning, architecture
review, quality gates, cost discipline, and session handoff — using lightweight
persistence files under `.workflow_artifacts/`. The primary runtime today is
Claude Code. A Codex adapter is scaffolded through repo-local `AGENTS.md`
guidance and `quoin/adapters/codex/`.

## Main Code And Documentation Areas

- `README.md`, `CHANGELOG.md`: top-level user documentation.
- `AGENTS.md`: Codex-facing repo-local guidance and architectural constraints.
- `quoin/CLAUDE.md`, `quoin/QUICKSTART.md`, `quoin/SETUP.md`: Claude adapter
  user-facing docs and command reference.
- `quoin/install.sh`: Claude adapter installer; copies skills to `~/.claude/`.
- `quoin/skills/<name>/SKILL.md`: 21 skill definitions deployed as Claude slash
  commands.
- `quoin/core/workflow/`: runtime-neutral rules (`rules.md`), artifact layout
  (`task-layout.md`), session-state, cost-ledger, and skill metadata.
- `quoin/core/skills/`: portable intent documents for all 21 skills.
- `quoin/core/scripts/`, `quoin/scripts/`: canonical + wrapper scripts for
  validation, path resolution, cost parsing, preamble build, and adapter-drift
  detection.
- `quoin/adapters/claude/`: Claude adapter documentation and models reference.
- `quoin/adapters/codex/`: Codex adapter scaffold — setup, readiness check,
  smoke test, feature manifest, and generated skill docs.
- `quoin/benchmarks/`: Phase 29 benchmark design (scenarios, templates, rubric,
  validator). Design-only; does not contain results.
- `quoin/dev/tests/`: ~62 pytest test files (~845 passing, 13 known failures).
- `quoin/memory/`: Tier 1 hand-edited runtime reference files (format-kit,
  glossary, terse-rubric, summary prompt, lessons-learned).

## How To Run Relevant Checks

```bash
python3 -m pytest quoin/dev/tests/                               # full test suite (~845 pass, 13 known fails)
python3 -m pytest quoin/dev/tests/test_benchmarks.py             # benchmark structure (6 pass)
python3 quoin/benchmarks/scripts/validate_benchmarks.py --project-root .   # benchmark manifest/scenario validation
python3 quoin/adapters/codex/verify_codex_readiness.py --project-root .    # Codex adapter readiness
python3 quoin/adapters/codex/smoke_codex_workflow.py --project-root .      # Codex workflow smoke
python3 quoin/scripts/build_preambles.py --check                 # preamble freshness check
```

## Top Risks And Unknowns For A Future Contributor

1. **Known test failures**: 13 tests fail pre-existing before this run.
   - `test_cost_from_jsonl.py`: 3 ccusage parity failures (version/timeout
     related; pre-existing).
   - `test_measure_v3_savings.py`: 5 failures due to missing
     `.workflow_artifacts/v3-stage-4-smoke/current-plan.md` fixture.
   - `test_path_resolve_e2e.py`: 5 failures related to resolver/inflight fixture
     assertions.
2. **Not a clean checkout**: Phase 29 benchmark files, parity matrix, and
   portability docs are untracked or modified, so git status is dirty. Cross-mode
   comparisons are provisional.
3. **Packaging state unclear**: `src/quoin/` contains only `__pycache__` files
   in this checkout; no Python package manifest (`pyproject.toml`, `setup.py`)
   was found. Packaging status needs separate confirmation before release work.
4. **Cost capture is Claude-specific**: The cost-from-jsonl tooling reads Claude
   Code `~/.claude/projects/` JSONL files. There is no equivalent for Codex.
5. **Codex adapter is scaffolded, not production-ready**: The Codex adapter
   README explicitly marks execution-loop and lifecycle skills as future work.
6. **§0 model dispatch preamble is generated**: Preamble sections in SKILL.md
   are generated by `build_preambles.py`. Hand-editing them causes CI drift
   failures.
