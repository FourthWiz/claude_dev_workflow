# Preamble guide — subagent prompt-cache warm-up

## Subagent preamble (Stage 2 of pipeline-efficiency-improvements)

The 9 spawn-target skills (critic, revise, revise-fast, plan, review, architect, gate, specify, enrich) read `__QUOIN_HOME__/skills/<skill>/preamble.md` as the FIRST step of their `## Session bootstrap`. This pre-warms the prompt cache for the §3 slice of `format-kit.md` plus `glossary.md`, so the explicit format-kit / glossary reads later in the same bootstrap (and the references at write-sites per `format-kit.md` §1 / lesson 2026-04-23) hit cache rather than cold-loading. The preamble is purely additive — every other bootstrap read remains in force, the write-site references remain in force, and a missing preamble.md falls through to today's behavior (no error). The mechanism is purely a token-cost optimization; it MUST NOT change skill outputs. The preamble is GENERATED by `quoin/scripts/build_preambles.py` at install time; never hand-edit; see `quoin/docs/spawn-bootstrap-audit-2026-04-28.md` for membership rationale and `§Discrepancies` for why /implement is not a target. The full-preamble target size is ~4 KB (1.2 KB §3 slice + 2.8 KB glossary + frontmatter); gate and the other stub-kind targets get a ~200-byte uniformity stub.

User-mode `bash install.sh` / `quoin install` never regenerates preambles — regeneration stays a `--dev`-only operation (`bash install.sh --dev` or `python3 quoin/scripts/build_preambles.py` directly). What user-mode installs now do is run an advisory `--check` and print a `[warn]` when the source-tree preambles are stale relative to `format-kit.md` / `glossary.md`; the check is silent when preambles are fresh, is skipped entirely outside a working clone (e.g. a wheel/site-packages install), and never affects the install's exit code. Opt out with `QUOIN_DISABLE_PREAMBLE_CHECK=1`.
