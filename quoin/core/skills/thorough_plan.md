# thorough_plan

Runtime-neutral intent for the thorough_plan skill. Any runtime adapter
(Claude, Codex, …) that implements this skill should match the contract
described here.

## Purpose

Orchestrate a planning convergence loop for a development task: invoke the
planning skill to produce `current-plan.md`, optionally run a critic-revise
loop to harden the plan, and emit a converged artifact ready for
implementation. The skill triages the task by complexity (Small / Medium /
Large) and routes to the appropriate planning depth. It does not produce plan
content itself — it coordinates the skills that do.

Deeper planning passes serve to strengthen evidence, tighten constraints,
sharpen acceptance criteria, improve sequencing, and ensure artifact
consistency before implementation begins. When scope or risk warrants
multiple rounds, the skill drives convergence to a PASS verdict before
handing off to the next phase.

## When to use

- When a development task requires structured planning before implementation
  begins.
- When the task is complex enough to benefit from an independent critic review
  of the initial plan (Medium or Large complexity).
- When a prior plan needs to be hardened through a critic-revise cycle before
  the implementation phase can start.
- As the universal planning entry point — routes Small tasks to a single pass
  and Medium/Large tasks to the full convergence loop.

## Inputs

- The user's task description (required).
- `<task-root>/architecture.md` — when produced by the architecture skill
  beforehand; missing file is a no-op.
- `<task_dir>/current-plan.md` — when a prior plan exists and needs revision;
  missing file triggers a fresh plan.
- Prior `<task_dir>/critic-response-*.md` files — for convergence-loop
  resumption; missing files indicate round 1.
- `.workflow_artifacts/memory/lessons-learned.md` — past insights that should
  inform the planning pass; missing file is a non-fatal skip.
- Optional knowledge cache under `.workflow_artifacts/cache/` — advisory;
  absence is a non-fatal skip.

All reads MUST tolerate missing files. The skill MUST honor the stage-aware
path resolver when locating `<task_dir>`.

## Output

A converged artifact at `<task_dir>/current-plan.md` (Class B per the
artifact-format contract), prefixed with a `## Convergence Summary` block
recording the task profile, round count, final verdict, key revision themes,
and any remaining concerns.

The closed top-level section set mirrors the planning skill's output:

- `## For human` — human-facing summary (≤12 lines; generated by the adapter).
- `## State` — YAML block: task name, stage, round, profile.
- `## Tasks` — terse numbered list with status glyphs and acceptance bullets.
- `## Decisions` — caveman prose; omit if no non-trivial decisions.
- `## Risks` — markdown table: id / risk / likelihood / impact / mitigation / rollback.
- `## Procedures` — pseudo-code steps (optional).
- `## References` — terse list; only when cross-references exist.
- `## Revision history` — terse changelog; only when prior rounds exist.

The skill also spawns the gate skill (via the adapter's mechanism) after
convergence, and updates a session-state file under
`.workflow_artifacts/memory/sessions/`.

## Behavior contract

- The skill MUST NOT produce plan content itself. It invokes the planning
  skill, the critic skill, and the revision skill as coordinated agents.
- The critic skill MUST run in a fresh context — the runtime adapter is
  responsible for ensuring context isolation between rounds.
- The convergence loop stops when ANY of these conditions is true:
  (a) the critic skill emits a PASS verdict;
  (b) the maximum round cap is reached;
  (c) the same dominant structural issue class recurs across consecutive
      rounds, triggering escalation to the user.
- The skill MUST NOT auto-invoke the implementation phase. After convergence
  and gate, the skill STOPS and waits for an explicit user command to proceed.
- The skill MAY offer to produce a task feature spec when none exists (Medium/
  Large only, advisory/non-blocking); it passes the task spec path to the
  planner when present.
- Cost-ledger writes are mandatory when a task context is active.
  The ledger lives at `.workflow_artifacts/<task-name>/cost-ledger.md`.
- After the phase completes, the skill MUST emit a concise human-readable
  summary of the step's outcome to the user as its final message, independent
  of any gate rendering; the summary restates the artifact's substance in
  plain language because the stored artifact may be in a compressed format.
- The skill MUST tolerate missing optional inputs (architecture.md,
  lessons-learned.md, critic responses) without aborting.
- The skill MUST honor the stage-aware task layout by writing
  `current-plan.md` to the path resolved for the current stage (not always
  the task root). `architecture.md` and `cost-ledger.md` always stay at the
  task root.

## Out of scope

- Model tier choice per round — that is the runtime adapter's responsibility.
- Subagent dispatch mechanism for the planning, critic, and revision skills.
- The specific names of the planning, critic, revision, and gate skills used
  at runtime — those are adapter-specific.
- Gate invocation mechanism (inline vs. subagent) — adapter-specific.
- Stream-idle timeout retry policy — adapter-specific.
- Classifier invocation for same-class recurrence detection — adapter-specific
  tooling; the contract specifies the behavior (escalate), not the tool.
- The BAIL-TO-IMPLEMENT synthesis decision — adapter-specific orchestration.

## v3-format detection rule

The format of `current-plan.md` is determined by the following verbatim rule.
Every runtime adapter that reads or writes a v3 plan MUST apply this rule
identically.

# v3-format detection (architecture.md §5.7.1 — copy verbatim)
# A file is v3-format iff:
#   - the first 50 lines following the closing `---` of the YAML frontmatter
#     contain a heading matching the regex ^## For human\s*$
# Otherwise the file is v2-format.
# On v3-format detection: read sections per format-kit.md for this artifact type.
# On v2-format (or no frontmatter): read the whole file as legacy v2.
# Detection MUST be string-comparison only — no LLM call (per lesson 2026-04-23
# on LLM-replay non-determinism).

## Notes

- The closed section set above is the contract; adapters MUST NOT silently
  introduce non-standard top-level sections.
- The runtime adapter owns: model tier per round, subagent dispatch,
  gate mechanism, classifier invocation for same-class detection,
  BAIL-TO-IMPLEMENT synthesis, and stream-idle retry policy.
- `architecture.md` always lives at the task root
  (`.workflow_artifacts/<task-name>/architecture.md`); `current-plan.md`
  lives at the stage-resolved path
  (`.workflow_artifacts/<task-name>/` or `.workflow_artifacts/<task-name>/stage-N/`).
- The `## Convergence Summary` prefix block is REQUIRED at the top of the
  output artifact; it signals convergence status to downstream gate and
  review phases.
- For Small-complexity tasks, there is no critic-revise loop; a single
  planning pass produces the output with `Rounds: 1` in the convergence
  summary. The runtime adapter controls the triage criteria and routing.
