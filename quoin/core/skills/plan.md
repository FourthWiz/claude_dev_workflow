# plan

Runtime-neutral intent for the plan skill. Any runtime adapter (Claude,
Codex, …) that implements this skill should match the contract described here.

## Purpose

Produce or update a concrete, implementation-ready planning artifact
(`current-plan.md`) for a development task. The skill identifies scope,
constraints, risks, and next actions; decomposes work into independently
reviewable tasks; and ensures integration points receive extra scrutiny.
The output artifact is the authoritative specification that downstream
phases (implementation, review, gate) execute against.

## When to use

- When an architecture document exists and work needs to be decomposed into
  executable tasks.
- When a direct user request describes work that requires structured planning
  before implementation.
- When revising an existing plan in response to a critic round (the adapter
  may route this to a separate revise skill).
- When no architecture document exists and the user wants a plan directly
  from a codebase description.

## Inputs

- `<task-root>/architecture.md` — when present, the authoritative stage
  decomposition; missing file is a no-op.
- Active session state under `.workflow_artifacts/memory/sessions/` — used
  to detect the current round and avoid re-reading stale information.
- `.workflow_artifacts/memory/lessons-learned.md` — past insights that
  should inform the plan.
- Prior `<task_dir>/critic-response-*.md` files — when this skill is
  invoked as part of a convergence loop; missing files are a no-op.
- The project source code — targeted reads for files the plan will affect.
- Optional knowledge cache under `.workflow_artifacts/cache/` — advisory;
  absence is a non-fatal skip.

All reads MUST tolerate missing files except when a critic response is
explicitly required (convergence-loop mode). The path to `<task_dir>` is
resolved by the runtime adapter's path-resolution mechanism using the task
name and optional stage identifier.

## Output

A single artifact at `<task_dir>/current-plan.md` (Class B per the
artifact-format contract). The closed top-level section set is:

- `## For human` — human-facing summary (≤12 lines; generated by the adapter).
- `## State` — YAML block: task name, stage, round, profile.
- `## Tasks` — terse numbered list with status glyphs and acceptance bullets.
- `## Decisions` — caveman prose; omit if no non-trivial decisions.
- `## Risks` — markdown table: id / risk / likelihood / impact / mitigation / rollback.
- `## Procedures` — pseudo-code steps; optional.
- `## References` — terse list; only when cross-references exist.
- `## Revision history` — terse changelog; only when prior rounds exist.

The skill also updates a session-state file under
`.workflow_artifacts/memory/sessions/`.

## Behavior contract

- The plan MUST be concrete: file paths, function signatures, data shapes.
  "Add a new service" is not a task; "Create `src/services/foo.py`
  implementing `process(id: str) -> Result`" is a task.
- The plan MUST read actual source code — not just the architecture doc.
  Assumptions about file structure or API shapes must be verified.
- For exploratory tasks, the plan MUST verify that a proposed feature does not already exist (searching source and recent history) before planning to build it, and MUST verify project conventions against real files before relying on them.
- Integration points MUST receive extra scrutiny; trace data flows end-to-end.
- Each task MUST be independently reviewable and produce a testable unit.
- Testing is not optional: every task touching code must carry test
  expectations.
- The skill MUST NOT auto-invoke downstream phases (implementation, review,
  gate, or finalization).
- The skill MUST tolerate missing optional inputs (architecture.md,
  lessons-learned.md, critic responses) without aborting.
- The skill MUST honor the stage-aware task layout by writing `current-plan.md`
  to the path resolved for the current stage (not always the task root).
- Cost-ledger writes are mandatory when a task context is active.
  The ledger lives at `.workflow_artifacts/<task-name>/cost-ledger.md`.
- When requirements are ambiguous the skill MUST ask the user before planning.

## Out of scope

- Implementation of any code.
- Review or gate decisions.
- Runtime-specific dispatch (model selection, subagent spawn mechanism).
- Choosing the model tier — that is the runtime adapter's responsibility.
- Choosing the summary-generation mechanism (`## For human` block) — that
  is the runtime adapter's responsibility.

## v3-format detection rule

The format of `current-plan.md` is determined by the following verbatim rule.
Every runtime adapter that reads or writes a v3 plan MUST apply this rule
identically.

# v3-format detection (architecture.md §5.7.1 — copy verbatim)
# A file is v3-format iff:
#   - the first 50 lines following the closing `---` of the YAML frontmatter
#     contain a heading matching the regex ^## For human\s*$
# Otherwise the file is v2-format.
# On v3-format detection: read sections per format-kit.md for this artifact type.
# On v2-format (or no frontmatter): read the whole file as legacy v2.
# Detection MUST be string-comparison only — no LLM call (per lesson 2026-04-23
# on LLM-replay non-determinism).

## Notes

- The closed section set above is the contract; adapters MUST NOT silently
  introduce non-standard top-level sections.
- Task numbering, cross-references, and dependencies must remain coherent
  across revision rounds; the `## Revision history` section tracks this.
- The runtime adapter chooses the model tier and the `## For human` summary
  generation mechanism; both are out of scope for this contract doc.
- `architecture.md` always lives at the task root
  (`.workflow_artifacts/<task-name>/architecture.md`); `current-plan.md`
  lives at the stage-resolved path
  (`.workflow_artifacts/<task-name>/` or `.workflow_artifacts/<task-name>/stage-N/`).
