# architect

Runtime-neutral intent for the architect skill. Any runtime adapter (Claude,
Codex, …) that implements this skill should match the contract described here.

## Purpose

Produce a detailed architectural plan (`architecture.md`) for a development
task by scanning the codebase, synthesizing findings, and decomposing the
work into independently implementable stages. The skill establishes the
authoritative design document that downstream planning, review, and critic
phases execute against. Output covers context, current state, proposed
architecture, integration analysis, risks, de-risking strategy, stage
decomposition, and open questions.

## When to use

- When a user needs to explore a complex system, understand how multiple
  repositories interact, or design a new architecture.
- When a development task is large enough to require explicit stage
  decomposition before planning begins.
- When prior `architecture.md` is absent or stale and downstream planning
  phases require an authoritative design document.
- When cross-cutting questions about a codebase cannot be answered without
  a structured scan and synthesis pass.

## Inputs

- Project source code — read via the runtime adapter's scan mechanism.
- Existing `/discover` output under `.workflow_artifacts/memory/` (advisory;
  absence is a non-fatal skip).
- Optional knowledge cache under `.workflow_artifacts/cache/` (advisory;
  absence is a non-fatal skip).
- Active session state under `.workflow_artifacts/memory/sessions/` — used
  to detect prior scan context and avoid redundant work.
- Optional prior `architecture.md` at `<task-root>/architecture.md` — when
  present, the skill revises rather than creates from scratch.
- Optional task feature spec at `<task-root>/spec.md` (read-if-exists;
  upstream intent whose acceptance criteria the design must satisfy).

All reads MUST tolerate missing files. The skill MUST ask the user for
clarification when the problem space is ambiguous before proceeding.

## Output

A single artifact at `<task-root>/architecture.md` (Class B per the
artifact-format contract). `architecture.md` ALWAYS lives at the task root
regardless of stage layout:
`.workflow_artifacts/<task-name>/architecture.md`

The closed top-level section set is:

- `## For human` — English summary ≤12 lines (generated by the adapter's
  summary mechanism).
- `## Context` — caveman prose: problem, constraints, business context.
- `## Current state` — caveman prose: how things work today, pain points.
- `## Proposed architecture` — prose + component diagrams where helpful.
- `## Integration analysis` — table (≥2 integration points) or terse list.
- `## Risk register` — markdown table: id / risk / likelihood / impact /
  mitigation / rollback.
- `## De-risking strategy` — caveman prose (optional section).
- `## Stage decomposition` — terse numbered list with status glyphs and
  acceptance bullets per stage; for each stage: scope, exclusions,
  prerequisites, complexity (S/M/L/XL), key risks, testing strategy,
  rollback plan.
- `## Stage Summary Table` — markdown table: Stage / Description /
  Complexity / Dependencies / Key Risk.
- `## Next Steps` — terse list of which stages are ready for the planning
  skill and in what order.
- `## Open questions` — terse list (optional; only if genuine ambiguities
  remain).
- `## Appendix` — supplementary material (optional).
- `## Revision history` — terse changelog if this is a revision (optional).

The skill also updates a session-state file under
`.workflow_artifacts/memory/sessions/`.

## Behavior contract

- The skill MUST scan the actual source code before producing architecture.
  Assumptions about file structure or API shapes must be verified.
- For exploratory tasks, the skill MUST verify that a proposed feature does not already exist — searching the actual source and recent history — before asserting in `## Current state` that the feature is absent or proposing a build stage. The skill MUST also verify project conventions (e.g., cross-reference/link styles) against real files before asserting them, since documented conventions can drift from reality.
- Integration points MUST be explicitly mapped across all repos or services
  involved in the task.
- The skill MUST produce a `## Stage decomposition` section that downstream
  planning and critic phases can consume. Each stage must be independently
  reviewable and provide incremental value.
- The skill MUST read the task feature spec when present and satisfy its
  acceptance criteria in the synthesis; it MAY offer to produce one when
  absent (advisory, non-blocking); it MUST tolerate its absence.
- After producing `architecture.md`, the skill MUST run an internal critic
  loop (Phase 4) to verify the architecture before returning it as final.
  The runtime adapter controls the convergence policy (max rounds, strict
  mode) — this is out of scope for the contract doc.
- The skill MUST NOT auto-invoke downstream phases (planning, implementation,
  review, gate, or finalization).
- The skill MUST tolerate missing optional inputs (discover output, cache,
  session state) without aborting.
- Cost-ledger writes are mandatory when a task context is active.
  The ledger lives at `.workflow_artifacts/<task-name>/cost-ledger.md`.
- When requirements are ambiguous the skill MUST ask the user before
  proceeding.

## Out of scope

- Implementation of any code.
- Planning or review decisions.
- Runtime-specific dispatch mechanism (scan/synthesize split, subagent
  spawn mechanism, model tier choice).
- Choosing the model tier — that is the runtime adapter's responsibility.
- Choosing the summary-generation mechanism (`## For human` block) — that
  is the runtime adapter's responsibility.
- Phase-4 internal critic loop convergence policy (max rounds, strict mode,
  recursive-self-critique guard) — all adapter-specific.

## v3-format detection rule

The format of `architecture.md` is determined by the following verbatim rule.
Every runtime adapter that reads or writes a v3 architecture doc MUST apply
this rule identically.

# v3-format detection (architecture.md §5.7.1 — copy verbatim)
# A file is v3-format iff:
#   - the first 50 lines following the closing `---` of the YAML frontmatter
#     contain a heading matching the regex ^## For human\s*$
# Otherwise the file is v2-format.
# On v3-format detection: read sections per format-kit.md for this artifact type.
# On v2-format (or no frontmatter): read the whole file as legacy v2.
# Detection MUST be string-comparison only — no LLM call (per lesson 2026-04-23
# on LLM-replay non-determinism).

## Notes

- `architecture.md` ALWAYS lives at the task root
  (`.workflow_artifacts/<task-name>/architecture.md`); it is never placed
  under a stage subdirectory. This is the single source of truth for all
  downstream phases.
- The closed section set above is the contract; adapters MUST NOT silently
  introduce non-standard top-level sections.
- The runtime adapter chooses the model tier, the scan/synthesize split
  mechanism, the summary-generation approach, and the Phase-4 convergence
  policy; all are out of scope for this contract doc.
- The runtime adapter's internal Phase 4 critic loop produces
  `architecture-critic-N.md` files at the task root (never under a stage
  subdirectory — corollary of the task-root invariant above).
- Stage decomposition in `## Stage decomposition` enables the planning skill
  to resolve per-stage artifact paths via the path resolver.
